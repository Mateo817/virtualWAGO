# WP-XE164-439 — independent review of frozen WP432

**VERIFIZIERT, bounded raw-source review.** The pinned FW31 `libpackbus.so.1.0.1` bytes support the 108-word contiguous slice `0x9618..0x97c4` and ten literal words at `0x97c8..0x97ec`; all are uniquely file-backed by PT_LOAD. WP432's own validator and immutable manifest also pass. The active REA target recorded in WP432 was a different image, so this review treats the range as a retained raw slice and control-flow evidence, not a matching REA procedure extent or authoritative function boundary.

The entry instruction `PUSH {r4,r5,r6,r7,r8,lr}` saves **six words total**: five GPRs (r4-r8) plus LR, 24 bytes. The next instruction reserves 120 local bytes; combined with the saved words, the entry stack decrement is 144 bytes. WP432's phrase “six-register/LR push” is ambiguous and should be read/corrected as “six total words: r4-r8 and LR,” not six GPRs plus LR. Epilogues add back 120 bytes and pop those five GPRs plus PC.

The callsite evidence from frozen WP430 is exact and conditional: the `0xa528` BL targets `0x9618`, after `0xa520` sets `r1=14` and `0xa524` copies the caller's current r5 to r0. In the helper, `0x962c` copies entry r1 to current r5 and `0x9634` copies entry r0 to current r8. `0x9628` establishes current r6=SP and `0x9624` establishes current r7=SP+60. Thus the source immediately before the first opaque call has r5=14 and r8=entry r0, under the caller's cited state.

The first primary call at `0x9670` is opaque. The later `cfsetspeed` setup uses **current** r5 (`MOV r1,r5` at `0x967c`), not a fresh reload from entry r1. Consequently, the vector `(r0=SP,r1=14)` is established only if the first `tcgetattr` returns normally and leaves r5 equal to its entry value. This is a needed explicit preservation premise, not an ABI rule. Similarly, later vectors using current r8/r6/r7 and local buffers depend on relevant earlier opaque calls not changing those registers or memory, unless the local source rewrites them. WP432 generally discloses unknown opaque effects, but its call-vector row stating `r1=14(saved entry r1)` should be qualified as “current r1=r5; equals 14 if first tcgetattr preserves r5.” The same conditional framing applies to later FD/buffer arguments.

Before the first call, the source zeroes q8 and uses d16 (the low 64 bits of q8) and d16-d17 in VSTR/VST1 stores. With current r6=SP and r7=SP+60, the fourteen listed stores cover the entire half-open range `[SP,SP+120)`. Two pairs overlap by four bytes each: `[48,56)` with `[52,60)`, and `[108,116)` with `[112,120)`. Because each write operand is zero initialized, the final local bytes are zero before the first external call, assuming the stack addresses are writable. The first VST1 instruction's disassembly includes the `:64` alignment qualifier; this review confirms that source operand only and does not infer a platform ABI or claim that entry SP alignment was established.

The five primary callsites are four configuration-named calls plus one memcmp: `tcgetattr(FD,SP)`, `cfsetspeed(SP,current-r5)`, `tcsetattr(FD,0,SP)`, `tcgetattr(FD,SP+60)`, and `memcmp(SP,SP+60,60)`. The equality of `current-r5` to 14 is conditional on the first `tcgetattr` preserving r5. The `cfsetspeed` r0 argument is current r6 and equals SP only if that same call leaves r6 unchanged. Later FD and buffer vectors use current r8/r6/r7 after preceding opaque calls, so those equal the entry FD/SP/SP+60 only under corresponding preservation premises. WP432's matrix row C3 says “four primary PLT calls,” while its call vector and effects ledger correctly contain five primary sites; clarify C3 as four configuration calls plus memcmp (five primary callsites).

The four config-call results are each captured in r4 by `SUBS r4,r0,#0`; signed-negative results branch to their corresponding logger and then return the captured result, conditional on normal opaque logger returns and usable frame/r4 state. For the final comparison, `SUBS r4,r0,#0` followed by `BNE` sends exactly zero to the zero-return epilogue. Any nonzero value goes to the mismatch lane, where `MVN r4,#0` sets the local result to `0xffffffff`, followed by logging and the shared return. No semantic meaning is assigned to these numeric results.
