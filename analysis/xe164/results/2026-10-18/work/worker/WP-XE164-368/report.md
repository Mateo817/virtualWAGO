# WP-XE164-368 — independent audit of the VPI numeric producer source

WP368 author **Self-Review**. **VERIFIZIERT** for the stated raw-code arithmetic, branch conditions, and direct store footprints in frozen WP352/WP355. The read-only checker independently matches all 163 exact-body words and nine bounded callback-slice words to the pinned ELF, plus all eleven pool words, then recomputes the selected PC/literal arithmetic, branch destinations, numeric boundaries, and store spans. **OFFEN**: public API/field meanings, ABI guarantees, actual callback invocation, lock/once semantics, dynamic binding, persistence/lifecycle, opaque call effects, and runtime behavior. Native/runtime/VM/device/network execution: **NOT_RUN**.

The subject remains the exact FW31 `libpackbus.so.1.0.1` (SHA-256 `3b7b7ca4fa14e5994552040a7b40b1cfbbf43e0649a4ad9277ece421fd4bc5d6`). Frozen WP352 and WP355 manifest digests match their stated hashes, and every file in both manifests was checked without running either package’s validator/generator. The body extents contain 63 `ulGetDigOffset` words, 88 `ulSetDigOffset` words, and 12 `vResetDigOffset` words. Nine more words are the bounded `[0x14774,0x14798)` callback candidate slice; the final word at `0x14798` is a literal, not a tenth instruction.

Raw PC-relative calculations from the eleven LDR literal words and following ADD words independently yield base B at ELF/module RVA `0x47bac` (Ghidra `0x57bac`) for the getter, setter, reset body, and bounded callback slice. The three callback-address calculations yield ELF/module RVA `0x14774` (Ghidra `0x24774`). These are numeric source addresses. The three function bodies pass B+`0x30` and this callback candidate to a call at ELF `0x78a8`, whose dynamic implementation and whether it calls the candidate remain unknown. The bounded candidate zeroes B through B+`0x2f` in one 16-byte store and four 8-byte stores, then branches to ELF `0x77d0`. This establishes only the nine bounded instructions; it is not a recovered complete function or observed callback execution.

For `ulGetDigOffset`, the instructions capture entry `r0` in `r7`, entry `r1` in `r4`, and entry `r2` in `r5`. After the once-named call, the code tests current `r4` and then current `r5` for zero. A zero value sets numeric `r0=1` and returns before the query call or output stores; this is a zero comparison, not a pointer validity check. If both are nonzero, the query call receives zero in `r0-r3` and current stack output locations in its output arguments. The query return word in current `r0` is not tested; the following code reads current stack words Q0/Q1. It requires current `r4/r5/r7`, stack outputs, and selected B halfword memory to have the expected values after opaque calls.

The getter selects Q0 from current `[sp+0x10]` when current `r7==0`, with global halfword B+`0x18`; otherwise it selects Q1 from `[sp+0x14]` and B+`0x24`. Raw `CMP #0x80000` followed by `CS`/`CC` instructions computes the halfword `min(Q>>3,0xffff)`. Its local numeric result is 0 for Q<`0x80000`, and 2 for Q>=`0x80000`; equality takes the saturated lane. It stores the halfword through current `r5`, then reads the selected B halfword. Nonzero global halfword is stored through current `r4`. If it is zero, the source stores zero through `r4`, reloads current `[r5]`, and stores that value through `r4`. Thus the fallback depends on address aliasing and memory changes during that sequence. For example, if r4==r5 but the output address is distinct from the selected B field, and that B halfword is zero, the first fallback clear overwrites the clamp value, so the later reload yields zero. If the output aliases the selected B field, the earlier clamp store can change the global value before it is read. No alias or pointer-range check exists in the audited words.

For `ulSetDigOffset`, entry `r0` is captured in current `r4` (selector) and entry `r1` in current `r5` (value); B is in current `r6`. The query call is made before the current `r5==0` gate. On the zero-value path, the query output words are not consumed; selector zero stores a halfword zero at B+`0x18` and eight vector-zero bytes at B+`0x1c..0x23`, leaving +`0x1a..0x1b` untouched. Nonzero selector stores zero at B+`0x24` and eight bytes at B+`0x28..0x2f`, leaving +`0x26..0x27` untouched.

On nonzero-value paths, raw `CMP r5,r3,LSR #3` and `BHI` compare the current unsigned value to the current Q word shifted right by three. For selector zero, Q0 is current `[sp+0x10]`: greater selects update, equal selects the zero lane, less returns numeric 1 without the local B update. For nonzero selector, Q1 is current `[sp+0x14]`: greater selects update, unequal selects numeric 1, equality selects the zero lane. The output words in the query frame and the copied payload words at `[sp+0x18]/[sp+0x20]` or `[sp+0x1c]/[sp+0x24]` are distinct.

The finite truncation case recomputes as `524280 >> 3 = 65535`; unsigned `65536 > 65535`, so the greater-than update path is selected, while `STRH 65536` stores the low 16 bits, zero. Selector zero stores words from current stack offsets +`0x18` and +`0x20` at B+`0x1c` and B+`0x20`; selector nonzero stores the low halfword at B+`0x24` and the 8-byte current pair at B+`0x28..0x2f`. This is a numeric source property, not evidence of an application bug, a public range rule, or unsafe behavior.

`vResetDigOffset` computes B and the callback candidate, calls the once-named target with B+`0x30` and callback address, then zeroes q8 and writes 16 bytes at B+`0x18` plus 8 bytes at B+`0x28`, exactly covering B+`0x18..0x2f`. The remaining instructions through the pop do not write r0, and the pop restores only r4 and PC. Therefore, on a normal path reaching that epilogue, the current opaque call return word in r0 flows back unchanged. Its meaning is not established.

Every post-call conclusion is conditional on the necessary current registers, frame/stack contents, query outputs, valid readable/writable locations, and any B/global-memory values being available and retained across the opaque calls. In particular, the code does not prove that r4-r7, SP, B, or the query frame are preserved by an ABI. These source checks establish numeric producer behavior only; they do not establish a complete API contract, value units, selector names, lock behavior, or object lifecycle.
