# WP-XE164-340 — bounded marshaller dispatch and selected source-step fixtures

**VERIFIZIERT (static, hash-bound):** The pinned libdal body at ELF `0x2784` reads the type-object halfword at `+6`, selects through two inline 15-branch instruction tables, builds temporary argument cells, and reaches a BL at ELF `0x28ac` with the numeric register values in `call-boundary.tsv`. The trace records were generated by `stepper.py` from the pinned source words; `validate.py` independently reruns that model in memory and compares the frozen trace artifacts. No hand-authored PC sequence is used by the model. **HYPOTHESE:** A constructed metadata row and reachable caller state could supply the modeled inputs. **OFFEN:** Runtime construction/reachability, binding, the `ffi_call` thunk’s resolved destination/effects, ABI or C varargs interpretation, and all callback behavior. Runtime, native execution, VM, target, device, network and hardware tests are **NOT_RUN**.

## Wrapper and path premises

The O+0x70 wrapper source starts with `stmdb sp!,{r1,r2,r3}`, then saves LR and reserves eight local bytes. Let entry SP be `S`. Its later `add r2,sp,#0x10` therefore sets `r2=S-8`, the address of the saved entry `r2` word followed by saved entry `r3`; the body call reaches O+0x74 at ELF `0x2784`. The wrapper also reloads saved entry `r1` from `S-12`. The metadata argc may exceed the two words in that saved range, so any additional caller argument words require a separate readable-stack premise. This establishes the wrapper’s source accesses, not a runtime caller convention.

The source-step boundary begins at ELF `0x27c8`, after opaque global/name/type lookup calls and the nonzero-return gate. The fixture stipulates current `r5` as a selected record pointer, `r6` as output destination, `r4` as a readable array of 32-bit argument words, `r11`/SP as the current frame, and nonzero `r0` for the success edge. The selected record bytes at `+4`, `+0xc`, `+0x10`, and `+0x14`, the type objects, and the stack ranges are synthetic, disjoint and readable/writable as recorded in `boundary-premises.tsv`. No register preservation across the earlier opaque calls is inferred.

## Argument and call-entry findings

The argument dispatch at ELF `0x282c` is `ADDLS pc,pc,lr,LSL #2`; its 15 inline branch instructions occupy `[0x2834,0x2870)`. They are executable A32 `B` instructions, not a data pointer table. The halfword at each type-object `+6` controls selection. For the tested versioned object fields, tag 5 reaches ELF `0x2918` and stores the input word’s low byte into an 8-byte temporary; tag 7 reaches `0x2900` and stores the low halfword; tags 9 and 14 reach `0x2880` and store the full word. The source then records each supported temporary’s address in its argument-vector cell. `argument-dispatch.tsv` gives the exact paths and fixture observations.

Three call-entry cases were source-stepped instruction by instruction:

- One four-argument fixture with tags `[5,7,9,14]` copied `0x11223344 → 0x44`, `0x55667788 → 0x7788`, `0x99aabbcc → 0x99aabbcc`, and `0xddeeff00 → 0xddeeff00`. At the BL, registers were `r0=0x1008`, `r1=0x0abcde00`, `r2=0x8ff8`, `r3=0x8fe8`; `r7=0` and SP was `0x8fc8`.
- A zero-argument fixture takes the source branch around vector allocation. At the BL, `r3=0`, `r2=0x8ff8`, `r7=0`, and SP is `0x8ff8`.
- A fixture with unsupported tag 4 reaches its default source arm at ELF `0x2950`, setting `r7=0xffffffff`. It then loops onward and still reaches the BL. Its argument-vector cell is not written by this body path; the trace records `None` for that cell rather than treating the fixture’s initially zeroed memory as a source store.

Across all three cases, the BL is at ELF `0x28ac`, target ELF `0x1504` / analysis address `0x11504`. The source at `0x28a0..0x28ac` sets `r1` from `[r5+4]`, `r0` to `r5+8`, and `r2` to current `r8`; `r3` remains the source-built argument-vector base (or zero on the no-argument edge). These are instruction-level register values at a thunk boundary. They are not promoted to a C prototype or an ABI contract. Unsupported-tag `r7` likewise does not prevent this source from entering the thunk.

## Opaque return and return-copy lane

The second fixture starts at ELF `0x28b0`, after a **stipulated normal opaque return** from the `ffi_call` thunk. It supplies current `r5`, `r6`, `r7`, `r8`, and SP; stipulates their preservation for this return-path model; and places test bytes at scratch address `r8`. The source dispatch at ELF `0x28bc` is the second inline 15-branch instruction table, again executable `B` code in `[0x28c4,0x2900)`. Tags 5, 7, 9, and 14 copy respectively 1, 2, 4, and 4 bytes from `[r8]` to `[r6]`; the fixture’s `0x89abcdef` therefore yields `0xef`, `0xcdef`, `0x89abcdef`, and `0x89abcdef`. The source status register `r7=0` becomes `r0=0` at the modeled return lane. Unsupported return tag 4 reaches ELF `0x2870`, sets the returned source word to `0xffffffff`, and performs no copy; the synthetic output sentinel remains unchanged. Traces stop at ELF `0x2878`, before the frame reset and register-pop epilogue. None of these fixtures assert what the opaque call actually returns, preserves, or writes.
