# WP-XE164-398 — selected full-source SSC_Open replay

**VERIFIZIERT** within the bounded source model: all 23 fetched SSC_Open instructions are replayed from the exact FW31 raw words with full `r0..r15`, PC, NZCV and per-instruction memory events; actual push/pop saves and restores the four listed registers and return PC. Runtime GOT provider, allocator behavior, actual allocation size, synchronization, object identity/reachability, API, ABI and hardware behavior remain **OFFEN**. Target/VM/network execution is **NOT_RUN**.

The model uses the pinned FW31 `libpackbus.so.1.0.1` (SHA-256 `3b7b7ca4fa14e5994552040a7b40b1cfbbf43e0649a4ad9277ece421fd4bc5d6`) and the exact 23 words at ELF `0xe008..0xe060`, independently checked through ELF32 `PT_LOAD` mappings. The literal at `0xe064` contains `0x363cc`, yielding the static global-cell address `G=0x443f4` from the instruction at `0xe020`. The body calls local PLT stubs at `0x7650` and `0x7a70`; their static relocation names are `MISC_threads_acquire_lock` and `pthread_mutex_unlock`. The model branches from each body BL to that PLT address, emits a separate opaque call event, and stipulates a normal return to the call’s LR. It does not run the PLT code, dynamic resolver, or provider. Runtime winner is open.

At entry, the source compares `r0` with 3 as unsigned, saves `r4-r6,lr` and then gates `I>3` to the local zero-result path. The fixtures show I=4 and `0xffffffff` reach that path without either opaque call. For I=0..3, the body reads `S0=[r5]`, passes `S0+0x2c` to acquire, then reloads `S1=[r5]` after acquire. It computes `Q=S1+8*I` and reads `[Q+0x60]`. If zero, it writes I to `[Q+0x5c]`, writes S1 to `[Q+0x60]`, and prepares result `Q+0x5c`. If nonzero, the result is zero. After unlock the body copies its current `r4` to `r0` and pops the saved frame. Therefore, under the fixture’s source-continuation premises, an empty slot returns `S1+0x5c+8*I`; an occupied slot and an out-of-range I return zero.

The call boundaries do not establish an ABI. To continue through acquire as modeled, `r4` must still hold I, `r5` must still designate G, the active SP and saved frame must remain intact, and the current G word must be readable. S1 is read after the opaque event, so it may differ from S0: a dedicated fixture changes G from S0=0x500000 to S1=0x520000. Its acquire argument remains S0+0x2c, subsequent field addresses use S1, and unlock receives S1+0x2c. No lock or object-identity semantics are inferred. On unlock return, the source needs `r4` still to contain its selected result and SP/frame intact for the `MOV r0,r4` and final POP. The reported object bytes also require the explicit event premise that unlock retains the eight selected field bytes. The negative controls demonstrate consequences if acquire clobbers r5/r4 or unlock clobbers result r4.

For I=3 the source-derived write interval is `[S1+0x74,S1+0x78)` and its selection read/write interval is `[S1+0x78,S1+0x7c)`. With the fixture mapped only through `[S,S+0x74)`, the first selection-word read at `0xe038` attempts `[S+0x78,S+0x7c)` and stops at the model’s unmapped-read boundary before either owner store or unlock. This is a model boundary, not a claim about a hardware exception or actual memory fault. A separate explicit `[S,S+0x7c)` fixture lets I3 take the empty path and return `S+0x74`. Comparing this with Init’s numeric `(1,0x74)` vector is conditional on interpreting the named calloc call conventionally and on S1 equaling that Init return S; the model establishes neither allocation extent nor actual bug.
