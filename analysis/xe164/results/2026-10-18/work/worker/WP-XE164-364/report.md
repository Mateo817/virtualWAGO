# WP-XE164-364 — selected source-stepped byte and bit helper paths

**VERIFIZIERT** for the selected, fully source-stepped paths and explicit synthetic byte maps below. Read/write effects beyond these traces, descriptor/API/ABI meaning, runtime reachability/binding, and native fault behavior remain **OFFEN**. The deterministic replay passes; native, VM, network, device, and runtime tests are **NOT_RUN**. This is a self-review, not an independent review.

Inputs are the frozen WP363 24-word `read_bits` and 50-word `write_bits` bodies from exact FW31 `libpackbus.so.1.0.1` (SHA-256 `3b7b7ca4fa14e5994552040a7b40b1cfbbf43e0649a4ad9277ece421fd4bc5d6`). Every executed PC and word is rechecked against WP363’s source TSV. Two code biases (`0x10000000`, `0x20000000`) exercise the branch table and return paths. Numeric addresses below are fixture addresses. Inputs are numeric register/state positions; no C type, API, or struct interpretation is added.

The two synthetic memory layouts keep `B`, `M`, the optional descriptor `D`, list `A`, output/source `Z`, and the helper stack frame disjoint. Separate cases intentionally set `Z=B+word[M+4]`. Every executed instruction records all `r0-r12`, SP, LR, NZCV flags, memory reads, and memory writes. The write helper’s push/pop and read helper’s single LR stack save/restore are replayed from actual instructions. Normal returns restore the starting SP; the code does not promise to restore every scratch register or LR register value. For the count-zero case, the memory map intentionally leaves `A-2` unmapped and the model stops at the actual halfword read there, before the subsequent negative-count branch. That is a model boundary, not a prediction of a native fault.

For `read_bits`, selector 1 first loads the current byte at `Z`, clears mask byte `M+9`, and stores the result. It then reads byte `B+word[M+4]`, tests it against `M+8`, and conditionally ORs `M+9` before a second store to `Z`. Disjoint cases exercise one-hot, multi-bit, and zero masks. In the alias case, the first store changes the same byte later read as the source. The validator checks that the source read observes this post-clear value and computes the output from that value. Selector 2 and selector 5 both take the encoded direct-copy lane in this helper. Each is traced with both disjoint `Z` and `Z=B+word[M+4]`; the aliased route reads and writes the same byte. Selector 3 returns without a store.

For `write_bits`, selector 1 clears `M+8` from byte `B+word[M+4]` and stores the cleared byte before loading `Z`; it tests the loaded source against `M+9`, conditionally ORs `M+8`, and stores again. One-hot, multi-bit, zero-mask, and `Z`-aliases-destination cases are traced. The alias validator checks that the `Z` read sees the earlier cleared destination value. Selector 2 copies byte `Z` to the selected buffer byte, including a same-byte alias case. Selector 5 stores `Z & M+8`, replacing the destination byte, with disjoint and same-byte-alias cases. Selector 3, selector 0 (unsigned underflow through the default branch), and selector 6 (above the inline table range) return without a selected destination store.

Selector 4 is replayed with current descriptor word `D=word[M+4]`, halfword `N=U16[D+2]`, word `A=word[D+4]`, and destination halfword `U16[D+8]`. These are source positions only. For `N=1,2,3`, the trace reads the last halfword offset first, uses the pointed-to byte as the XOR seed, and executes the encoded earlier-entry loop where applicable; it then writes one byte at the selected destination offset. The validator checks the executed source-byte read count equals the chosen N and recomputes the XOR over those trace-derived bytes. For `N=0`, the source computes `A-2`, attempts the halfword read at ELF PC `0xd528`, and only then could test the negative result. The deliberately unmapped fixture stops at that read; BMI and any store are not executed in this model.

There are 48 complete or bounded traces: 24 selected/control cases for each of two code biases, including alias and no-store lanes. `case-matrix.tsv` summarizes the inputs and outcomes; `traces.json` contains the complete register/flag/access histories. The read-only validator reconstructs traces from the pinned source, checks every fetched word, and independently checks the ordered alias effects, return stack, selected outputs, no-store branches, XOR counts/results, and the exact count-zero attempted read.

A separate WP361 review of WP353 identified that its full premise should retain all 15 post-BLX stack-read words, not only the four event words. WP353 remains untouched and is outside this model; WP364 records full stack reads for its own selected paths and makes no claim based on WP353. No upstream package was modified.
