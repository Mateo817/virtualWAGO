## Source and trace method

The exact subject is `libpackbus.so.1.0.1`, 148,792 bytes, SHA-256 `3b7b7ca4fa14e5994552040a7b40b1cfbbf43e0649a4ad9277ece421fd4bc5d6`. Root362's retained source table has 109 words and SHA-256 `760f08b0c722d755da7b7b2389bd32fcfae81a6cec51b4e10b5d37174a433186`; the selected five bodies contribute 48 words. Root362, WP369 and WP376 manifest hashes are retained and checked. The validator checks every Root362 instruction word at its raw ELF file offset, with Ghidra PC equal to ELF VA plus `0x10000`.

`model.py` fetches by PC only from those raw-word-pinned body entries. It decodes the selected A32 condition, branch, data-processing, load/store, push/pop, and BX forms. It models the exact selected VLD1.32, VREV64.32 and VST1.32 source words using an explicit 64-bit D16 value with two 32-bit lanes. For the vector sequence in `flip`, VREV64.32 reverses those lanes before the eight-byte store. The raw BL words determine the acquire/unlock target and link return PC; their callees are represented only by explicit boundary events.

The current object tuple is labeled **post-acquire fixture state**. The object bytes before acquire are sentinels and are not treated as the tuple. At acquire return, a premise event makes the stipulated `(I18,I1c,I20,B24)` tuple current, retains `r4=P`, SP and the stack frame, and clobbers unrelated scratch registers including r0. This closes the source-to-current-memory step without claiming the actual call establishes it. At unlock, a separate event records that the model assumes preservation of exactly the written/read object byte range `P+0x18..P+0x24`, plus the frame and SP. It clobbers r0/r4 and scratch registers. Consequently the source's following MOV and LDMIA, rather than any unlock register-preservation convention, establish the final local return state.

## Local behavior and fixtures

`get_read` and `get_write` take the nonnull index from `P+0x18` and `P+0x1c`, respectively, compute `P+4*index`, and return the word at the resulting pointer plus `0x2c`. `size` returns `[P+0x28]`. Their null routes skip conditional memory operations and return zero. The stipulated nonnull examples return `0x76543210`; `size` returns `0xabcdef01`. The OOB example uses `P=0x3000`, `I18=7`, and stops at the unmapped synthetic word `0x3048` before committing that load. This is only a mapped-memory boundary, not a native fault or general safety result.

The mutator fixtures use the six permutations of `(0,1,2)` and all three B24 values. `flip` uses the vector sequence to exchange I1c and I20, writes B24=1, then reaches unlock. Its final local result is `(I18,I20,I1c,1)`. `snapshot` reads B24 after acquire. If it is zero, the conditional index/flag stores skip; if it is 1 or 128, it writes B24=0 and exchanges I18/I20 while leaving I1c unchanged. Both normal-return paths set r0=0 and pop. Null mutator paths return 1 without either opaque event. These are source-path results under the explicit boundary conditions, not API semantics.

## Validation and limits

The optional `generate.py` writes the four artifact tables. Default `validate.py` imports the mathematical model with bytecode output disabled, reconstructs all scenarios in memory, compares the serialization to the frozen generated outputs, checks each path's source words and encoded conditional branch target, verifies stack and opaque premises, and recomputes finite outputs from the source formulas. It does not execute either frozen upstream generator. WP369's transform table is checked only after independent formula derivation; WP376's limitations about opaque object memory are handled by explicit post-acquire and unlock events here.

The fixture does not prove that the real acquire call supplies the tuple or preserves r4/frame/memory, or that unlock preserves the selected object bytes. No object identity, allocation zero-fill, synchronization, atomicity, API/ABI contract, constructor reachability, arbitrary index bound, runtime behavior, or physical effect is inferred. WP369 and WP376 remain unchanged.
