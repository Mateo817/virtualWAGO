# WP-XE164-343 — independent audit of the frozen WP331 libffi acquisition

**VERIFIZIERT (statisch, hashgebunden):** I independently checked the raw ELF identity, ELF32 load mappings, exact dynamic-symbol tuples and field bytes for the ten retained type objects, all 803 retained A32 instruction words, the numeric entry guard and stores, the `ffi_call` wrapper, the 8010 indirect-call boundary, and the seven-slot return dispatch. The pinned libffi is 46,764 bytes, SHA-256 `d162a9b28a30f10bd8baacac3a62b32148563e3b1e4d25c81361211d3172c4f5`. The frozen WP331 manifest SHA-256 remains `14a3b6ac08d79690d384fcf22c8b1f9ac35450d1823b79cff9a6240a3bcc0304`; every listed WP331 package file and its pinned inputs still verify. WP331 was not modified, and its builder and validator were not used as the audit oracle.

The raw program headers directly show an RX `PT_LOAD` at file offset/VA `0/0`, file size `0xa678`, and an RW `PT_LOAD` at file offset/VA `0xae60/0x1ae60`, file size `0x2bc`. All selected code addresses and the ten type-object addresses lie in the first segment, so their raw file offsets equal their ELF VAs. The retained REA addresses for selected code correspond to ELF VA plus `0x10000`. I independently read and compared all 803 words to the pinned raw file: `ffi_prep_cif` 326 words, `ffi_call` 7, internal `0x7194` body 300, thunks `0x8000`/`0x8010` 4/11, helpers `0x169ec`/`0x16fe8` 48/107. The `ffi_prep_cif` words occupy the two exact ranges `[0x235c,0x2468)` and `[0x7644,0x7a50)`. The word at `0x240c` is an unconditional branch to `0x7644`; counting the intervening addresses as body code would incorrectly include unrelated bytes.

`readelf` reports `ffi_prep_cif@@LIBFFI_BASE_8.0` as a 268-byte `FUNC` at `0x235c` and `ffi_call@@LIBFFI_BASE_8.0` as a 28-byte `FUNC` at `0x7a64`. These are symbol metadata extents. They do not describe the complete noncontiguous `ffi_prep_cif` body.

The ten direct `readelf` dynamic symbol tuples match `type-object-audit.tsv`: each is a 12-byte `OBJECT`, `GLOBAL`, `DEFAULT`, version `LIBFFI_BASE_8.0`, at its exact expected ELF VA. Independent raw reads confirm the values at offsets `+0`, `+4`, `+6`, and `+8`: pointer `(4,4,14,0)`, sint64 `(8,8,12,0)`, uint64 `(8,8,11,0)`, sint32 `(4,4,10,0)`, uint32 `(4,4,9,0)`, sint16 `(2,2,8,0)`, uint16 `(2,2,7,0)`, sint8 `(1,1,6,0)`, uint8 `(1,1,5,0)`, and void `(1,1,0,0)`. These are numeric source fields and exact symbol metadata only; this audit assigns no application-level or ABI meaning to them.

At `ffi_prep_cif` entry the raw source computes `r3=r1-1`, compares unsigned `r3` with 1, and branches `BHI` to a path that returns numeric 2 for all values outside the accepted numeric lanes. The accepted numeric lanes are `r1=1` and `r1=2`; no named ABI identity is inferred. On those lanes, source writes current `r1` at record `+0`, current entry `r2` at `+4`, the word loaded from entry SP at `+0x18` at `+8`, saved entry `r3` at `+0x0c`, and numeric zero at `+0x14`. Because the prologue pushes six registers (24 bytes), the `[sp,#0x18]` load addresses the entry-SP word. Further preparation work and helper effects remain outside a complete contract claim.

The seven-word `ffi_call` entry at `0x7a64` saves LR, reserves 12 bytes, writes zero at the new SP, calls `0x7194`, restores the 12 bytes, then returns through the saved PC. The selected internal source calls thunk `0x8010`; the `ffi_prep_cif` continuation calls the preceding four-word thunk at `0x8000`, which falls through to `0x8010`. In that source slice, `r1` is the current frame address: `stmia r1,{r11,lr}` saves the prior frame/link words there, then `r11=r1`, `sp=r0`, and `lr=r2`. The slice loads `r12=[r11+16]`, restores four argument registers from its current stack, and executes `BLX LR`. Thus the indirect target is the current entry `r2`, and normal return resumes at `0x802c`. The next source instructions reload `r2=[r11+8]` and `r3=[r11+12]`, set SP from current r11, and dispatch from PC `0x8040` plus `r3*8`. Continued execution requires explicit premises that the target returns normally and preserves the frame register and memory words later read or popped; no ABI preservation rule is assumed.

The first 56 raw bytes of the fallback decode to seven 8-byte slots, for indices 0 through 6: slot 0 stores S0; slot 1 stores D0; slot 2 stores D0–D3; slot 3 stores r1 at result+4 then falls through to slot 4, which stores r0; slots 5 and 6 return without a result store. Each path pops saved r11 and PC. This matches the retained bounded disassembly and the independent raw-word table. The retained REA `procedure_info` query explicitly reports that no procedure exists at Ghidra `0x18040`; this audit treats that as a metadata limit and does not promote bytes after ELF `0x8078` into a callable body. The larger 128-byte read is context only.

The static call and return boundaries match WP331’s report. The evidence does not close arbitrary signatures, complete `ffi_prep_cif` or `ffi_call` semantics, helper effects, runtime library selection, relocation results, faults, concurrency, or invocation. **OFFEN:** API/prototype/ABI meaning, runtime binding, full helper contracts, and all unselected code paths. No native, VM, device, network, or runtime tests were run.

**VERIFIZIERT:** independent read-only checker in `validate.py`. **PASS:** frozen manifest/source pins, raw PT_LOAD mappings, all 803 words, type symbol tuples and bytes, prep guard/stores/tail, call wrapper, indirect target/frame sequence, and bounded fallback slots.
