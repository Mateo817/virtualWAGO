# WP-XE164-417 — Selected source-stepped codec bodies

**VERIFIZIERT:** The 18-word no-argument encoder, 26-word one-argument encoder, 61-word Reply decoder, and 8-word last-error getter match the raw FW31 source and the local numeric models. The model covers 113 body words, four literal words, and 13 table halfwords across 63 independent-entry fixtures plus one separate-entry shared-global fixture. **OFFEN:** Public protocol/API meaning, runtime binding, ABI, actual pointer validity, and hardware behavior.

The source is the exact 148,792-byte FW31 `libpackbus.so.1.0.1` (SHA-256 `3b7b7ca4…fd4bc5d6`) pinned by WP414. The local source table contains only the four selected bodies, excluding the three PLT stubs in WP414's wider 122-word inventory. `validate.py` independently checks source-file hashes, PT_LOAD address-to-file mapping, all selected words and literal pools, the 13 table halfwords, and deterministic regeneration. `write_traces.py` is the separate writer. The default validator guards bytecode before imports, writes no files, and confirms its complete local inventory remains unchanged.

Each trace records every executed PC and raw instruction word; r0–r14, NZCV, D16/D17 before and after each instruction; each memory event; and complete explicit initial/final RAM-byte maps. Source data reads are identified as file-backed PT_LOAD reads. The fixture explicitly maps its stack, record, output, input, and global byte ranges. Stack bytes start at sentinel `0xa5`; stack reservation alone does not zero bytes. The global byte region E is an explicit fixture at numeric address `0x44410`, initially seeded with distinct bytes. That base is reconstructed locally from the source PC-relative instructions; zero initialization or lifecycle semantics are not inferred.

For each encoder, fixtures cover tags 0 through 12, 13, `0xffffffff`, and null output; one-argument fixtures also cover null argument and `Arg=Out+2`. Accepted no-argument cases write the selected table halfword's low/high bytes at Out+0/+1, then zero halfword at Out+2, and return0. Accepted one-argument cases write the table bytes, halfword1 at Out+2, then read the current halfword at Arg and write its low/high bytes at Out+4/+5. The alias fixture shows the read at Out+2 returning the just-written value1 and output bytes `…01 00`. Rejected fixtures return2 before these output stores. These are source offsets and byte effects, not public field definitions.

Reply fixtures set R+2 to the status halfword and R+4 to a count halfword; payload halfwords begin at R+6. At entry, the body reads both header words, stores the status low byte at E+Tag, and only then tests that low byte. A nonzero low byte returns1 even when count would mismatch. If status is zero, low8(count) is compared with the full current expected register: a mismatch returns2. With a match, N=0 or output pointer0 returns0 before copy. A `0x0100` status is locally zero because its low byte is zero; count word `0x0108` gives N=8 because the source truncates to its low byte; expected `0x101` does not match N=1.

The selected normal-copy fixtures cover N=1,7,8,9,16,255. The source chooses vector copying only when its unsigned `U32(O-R-7)>14` gate is high and N is at least8. In the mapped disjoint cases, each exact VLD1/VST1 pair transfers16 bytes and advances both current pointers by16; the remaining `N mod8` halfwords use the scalar loop. N=255 therefore executes31 vector iterations and7 scalar halfword iterations. The raw words are `0xf4620a4d` and `0xf44e0a4d`; both carry Rm=13. GNU objdump shows the post-index `!` writebacks omitted in the retained Ghidra text. The replay applies the raw architectural writebacks, and the trace confirms each pointer advances16.

Two deliberately mapped aliases expose source ordering. For O=R+8 and N=7, the unsigned distance gate selects scalar forward copying. The first read from R+6 is written at R+8, which is the next source halfword; later reads observe that write, so the seven outputs repeat the first value. This is the observed leaf behavior under this fixture, not a memmove guarantee. For O=R+6 and N=16, the selected vector path loads each 16-byte block before storing that same block at the same address, leaving the payload unchanged. No general overlap rule is claimed.

The last-error body checks unsigned Tag<=12; accepted tags read the current E+Tag byte, while 13 and `0xffffffff` return0 without an E-table load. An additional fixture runs Reply and last-error as two separate synthetic entry invocations over the same resulting E-byte image: Reply writes E+7=0x35 and the separate getter returns0x35. This demonstrates only the selected local memory relation; it does not claim Reply calls the getter.

No opaque calls occur in the four selected bodies. The model makes no claims about alignment faults, asynchronous modification, bounds checking, actual buffers, API/tag names, initialization order, public protocol, runtime binding, or the actual device. The only behavior conclusions apply to the pinned instruction words and explicitly mapped fixture bytes.
