# WP-XE164-410 — Independent review of WP-XE164-408

**VERIFIZIERT:** WP408's three numerical ioctl vectors, selected control-flow conditions, local status-byte handling, and static PLT identities agree with the pinned FW31 DSO. I found no incorrect flag, buffer position, or local return predicate. **OFFEN:** runtime binding and behavior, caller-supplied values, kernel/UAPI meaning, descriptor validity, and physical device effects.

I re-read all 181 selected instruction words and seven literal words from the exact 148,792-byte `libpackbus.so.1.0.1` (SHA-256 `3b7b7ca4…fd4bc5d6`) through independently parsed ELF32 little-endian PT_LOAD ranges. The three body extents contain 51, 39, and 67 words; the remaining 24 are eight three-word PLT stubs. The copies of WP408's source tables in `source/` are byte-for-byte bound to that DSO. I separately parsed dynamic `SHT_REL` records and confirmed the eight static PLT slots resolve to the names listed in WP408. These are relocation identities, not claims about runtime winners.

For ReadWrite, the call occurs with current SP equal to entry SP minus 40. Its vector is `(r0=word[handle+4], r1=0x40184b01, r2=A=SP+8)`. The six little-endian words at A are entry r1, entry r2, entry r3, SP+6, SP+7, and `0x5dc`. The two byte targets are zeroed first and have no later byte-load in the selected body. Command has the same frame size and uses `(word[handle+4], 0x401c4b02, SP+4)` with seven words: entry r1, entry r2, entry r3, word[entrySP], SP+2, SP+3, and `0x1388`. The load `[currentSP+0x28]` is exactly `[entrySP]`; this identifies a stack-relative source word, not a caller prototype. Its two local byte targets are initialized to zero and not later loaded as bytes.

Both handles take a null check followed by a signed comparison of `word[handle+4]`; the negative local path returns 1 before ioctl. The null CMP's flags survive the intervening SUB, MOV, and STRB instructions because those encodings do not set flags. After ioctl, each routine performs signed `CMP current r0,current r4`; interpreting the threshold as zero requires current r4 to remain zero. Nonnegative returns then become local result zero. Command's negative path reads the current errno word and maps `0x6e` to 2, other values to 1. ReadWrite makes strerror- and syslog-named calls before loading errno again; the later current value `0x3d` or `0x6e` maps to 2, otherwise 1. Pointer/register/frame continuity and current errno contents across these opaque calls remain premises.

Open's literal calculation reaches `/dev/kbus0\0` in a file-backed PT_LOAD range. It passes that pointer and numeric second argument 2 to the open-named PLT; this is only a source call vector. At the ioctl call, current SP is likewise entry SP minus 40, A is current SP+0x10, request is `0x40084b03`, and the eight bytes are `10 01 00 00 00 2d 31 01`. If the signed ioctl comparison succeeds with current r4=0, the routine calls the write-named PLT with `(current r5, SP+0xc, 4)` after writing word 1 at SP+0xc. It ignores that call's return before requesting `malloc(8)`. A nonnull current allocation result receives stores at offsets +4 from current r5 and +0 from current r6. The source sets r5 from the open result and sets r6 to 1 before intervening opaque calls; values F and 1 at those fields therefore require current r5/r6 preservation, including r6=1. WP408 states this condition generally as current GP/frame values; this review makes the exact r6 premise explicit.

The independent checker in `validate.py` verifies raw bytes, source extents, branch targets and condition encodings, MOVW/MOVT requests, every reported stack-store vector component, the Open config and path, status-byte nonreads, and static JUMP_SLOT bindings. It ran read-only and left its package inventory unchanged. No native ELF or device code was executed.
