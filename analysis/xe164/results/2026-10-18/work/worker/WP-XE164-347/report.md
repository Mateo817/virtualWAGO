# WP-XE164-347 — bounded integer `ffi_prep_cif` source fixtures

**VERIFIZIERT (statisch, hashgebunden):** Six bounded A32 replays follow the exact retained WP331 `ffi_prep_cif` words (326 words in two source ranges) and, for numeric mode `r1=2`, execute the exact 107-word helper at ELF `0x16fe8` for each supplied argument-type object. The three requested positive signatures, an argc-7 case, the accepted numeric `r1=1` comparison, and invalid numeric `r1=3` control are recorded in `matrices/fixture-summary.tsv` and `traces.json`. **PASS:** source-driven replay validator. **NOT_RUN:** native/runtime, VM, device, network, hardware, and public-header/API/ABI validation.

The source artifact is the exact 46,764-byte FW31 `libffi.so.8.1.4` pinned by WP331, SHA-256 `d162a9b28a30f10bd8baacac3a62b32148563e3b1e4d25c81361211d3172c4f5`. WP331’s frozen package manifest is pinned at `14a3b6ac08d79690d384fcf22c8b1f9ac35450d1823b79cff9a6240a3bcc0304`; the later independent WP343 audit manifest is also hash-pinned. The complete REA body/procedure records and extracted word tables are retained in `pins/`. This work uses those accepted, frozen inputs and does not import or edit the vendor library or upstream packages.

The `ffi_prep_cif` source body is noncontiguous: ELF `[0x235c,0x2468)` and `[0x7644,0x7a50)`. Its direct branch at `0x240c` joins those ranges. The second retained body is the exact classifier `[0x16fe8,0x17094)` (107 words). Each fixture begins at `0x235c`; the interpreter fetches only pinned words and stops at the supplied return sentinel. A BL to `0x16fe8` transfers into that exact helper body; its own executed words establish the numeric `r0=0` result and return to the call site. No helper result is injected by the fixture harness.

Synthetic entry premises are explicit: record address `0x10000`; entry SP `0x9000`; `[entrySP]` points at the supplied argument-type pointer array (or is zero for argc=0); entry `r1` is the numeric mode under test, `r2` is argc, and entry `r3` points to the selected return-type object. Exact local type objects are populated from WP331’s raw object words at `ELF VA + 0x500000`: pointer `(size 4, halfword +4 = 4, halfword +6 = 14)`, sint32 `(4,4,10)`, uint32 `(4,4,9)`, uint16 `(2,2,7)`, and uint8 `(1,1,5)`. The synthetic CIF and stack bytes are initialized to `0xa5`/zero to distinguish writes and untouched bytes. These are numeric fixture premises, not a claim that a constructor can produce the memory arrangement or that the runtime selects this artifact.

For all four `r1=2` cases, source returns numeric `r0=0` and restores SP to `0x9000`. The selected numeric fields are in the matrix. For argc 0, 2, and 3, source writes `0x10` at CIF `+0x10`; for argc 7 it writes `0x20`. It writes numeric `4` at `+0x14`, zero at `+0x18` and halfword `+0x1c`, and the mode-2 initialization writes sixteen `0xff` bytes to `+0x20..+0x2f`. The helper call tags match the supplied objects: `[5,14]`, `[9,7,14]`, and `[5,7,9,14,5,7,9]`; every helper path is instruction-stepped to numeric zero. The argc-zero case makes no helper calls.

The same `[uint8,pointer]` signature with numeric `r1=1` follows a different accepted source lane: the source returns numeric zero and restores SP, but does not call the integer classifier or take the mode-2 initialization path. Under the initialized sentinel memory, CIF `+0x18..+0x2f` remains `0xa5`. Numeric `r1=3` follows the source rejection path, returns numeric `2`, restores SP, and leaves the initialized 0x30-byte CIF region untouched. These are local source-path observations; the values are not named or mapped to public ABI constants.

The replay also records full per-instruction register snapshots, source PC/word/condition outcomes, memory stores, helper-call slices, and final CIF bytes.
