I independently checked WP388’s selected words against the pinned FW31 ELF by parsing its ELF32 program headers and resolving each code/literal VA through a unique file-backed `PT_LOAD`. The 45 `length` words at `0xd5f8..0xd6a8`, three PLT words at `0x81cc..0x81d4`, four getter words at `0xbec4..0xbed0`, and literal words at `0xd6ac`, `0xd6b0`, `0xd6b4`, and `0xbed4` match raw bytes. Their VA and file offsets happen to be equal for these locations. The decoded PC-relative calculations yield input mapping base `0x337d0`, getter base `0x4013c`, shared optional-global pointer cell `0x443f4`, and PLT slot `0x3349c`. The retained relocation row is `R_ARM_JUMP_SLOT` for `SSC_parse_get_content_lengths` with static symbol value `0xbec4`; the fixture writes `0xbec4` into that slot. That proves the selected local path under the fixture stipulation, not the loader’s runtime choice.

The review decoder re-evaluates each fetched word using the recorded pre-instruction GPR/NZCV state. It checks the computed post-state, conditional execution, branch or computed return destination, and each event’s address, width and write payload. It covers the actual push/pop list and stack addresses through the PLT/getter call and back to each body epilogue. For these inputs `r0` is the getter result `L = 0x4013c + 16*index`; the final pop restores `SP=0x600000` and returns to the fixture sentinel while preserving `r0=L`. This is a returned pointer value, not a success status.

The six actual stores are ordered at `0xd638`, `0xd644`, `0xd650`, `0xd65c`, `0xd680`, and `0xd6a4`, guarded respectively by entry `r1`, entry `r2`, `[entrySP]`, entry `r3`, `[entrySP+4]`, and `[entrySP+8]` being nonzero. Their source values are `L+0`, `L+4`, `L+0xc`, `L+8`, `globalBase + (index+2)*8`, and `globalBase + index*8 + 0x14`; the final two are shifted left three with 32-bit wrap. In the alias fixture, output0 targets `L+4`: the first store writes the `L+0` value there, and the later load at `0xd640` reads that changed word. The subsequent output1 store therefore receives the first output’s value. The all-null fixture takes the conditional pop at `0xd688`; the other three take the final pop at `0xd6a8`.
