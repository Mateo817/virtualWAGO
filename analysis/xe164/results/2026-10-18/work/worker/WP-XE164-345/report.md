Under the explicit conditional premise that each external `ffi_type_*@LIBFFI_BASE_8.0` reference resolves to the corresponding object in this exact candidate libffi, the selected argument metadata uses only numeric tags 5, 7, 9, and 14: 50 `uint8`, 15 `uint16`, 3 `uint32`, and 42 pointer objects. The candidate object's raw `+0`, `+4`, and `+6` fields supply the recorded size/tag values; the selected code uses tags 5/7/9/14. Other type objects and source tags exist in the pinned inputs, but no argument row selects them. This join establishes candidate metadata/source compatibility only; it does not establish a runtime binding or application-level type meaning.

The raw libdal handlers confirm that all four selected tags load one 32-bit word from the current source cursor and advance it by four bytes. Tag 5 stores one low byte, tag 7 stores one low halfword, and tags 9/14 store one word. Each selected handler reserves an eight-byte value slot and writes its address to the current vector element. The unused part of narrow slots is not initialized by those stores. The selected source handler targets are respectively `0x2918`, `0x2900`, and `0x2880` for tags 5, 7, and 9/14. These widths are source operations and numeric object fields, not varargs promotions or C prototype semantics.

All 28 return references are either tag 9 (`uint32`, two rows) or tag 10 (`sint32`, 26 rows), each with candidate size four. The return switch in libdal routes both tags to `0x299c`, which performs one 32-bit load from current `r8` and one 32-bit store through current `r6`. No sign interpretation or application meaning follows from this copy.

Recomputed per-row stack use is `32 + 8 + align8(4*n) + 8*n` bytes below the common-body entry SP immediately before the call: a 32-byte saved-register frame, an eight-byte return scratch allocation for the selected four-byte return types, an eight-aligned vector of four-byte pointers, and eight bytes per staged value. This gives 40 bytes at zero arguments and a maximum of 128 bytes for seven arguments. At zero arguments the vector allocation is skipped and the source passes `r3=0`. The calculation excludes WP330’s optional 24-byte wrapper frame and stack used by callees; it is a bound for these selected metadata rows and source path only, not a general ABI stack bound.

The raw code supports the join’s selected branch targets and arithmetic. General inputs can still select other source cases: tags 0/4/13/out-of-range have no selected argument metadata here, and WP341 shows that the error cases do not fail fast before `ffi_call`; they skip the source-value load and staging-slot write while advancing the vector cursor. After `ffi_call`, readable result memory, normal return, and preservation of live frame/register state required by the return suffix are also premises. None is inferred from a calling convention.

The optional WP330 entry wrapper saves only two input words from the incoming `r2`-based source range. Rows with more than two source words consequently need a separate readable-memory premise for later reads. This does not establish a caller convention or a C argument representation.
