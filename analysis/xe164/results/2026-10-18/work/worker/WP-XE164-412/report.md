# WP-XE164-412 — Selected full-source replay: SPI_ReadWrite and SPI_Command

**VERIFIZIERT:** The selected 51-word and 39-word procedures source-step consistently with WP408/WP410. Across 15 synthetic traces, the exact buffers, local guards, signed post-ioctl gate, errno paths, full stack restoration, and final local result agree with the raw words. **OFFEN:** Actual external-call effects, runtime bindings, ABI, request interpretation, and device/kernel effects.

The source is pinned FW31 `libpackbus.so.1.0.1` (SHA-256 `3b7b7ca4…fd4bc5d6`). This package contains only the 90 selected instruction words and the two literal words used by ReadWrite's logger sequence. Its pure source-stepper reads the pinned bytes and steps the actual A32 opcodes in the selected bodies. For every step, `traces.json` records PC, instruction word, all r0–r14, NZCV, memory event or opaque-boundary event, and resulting state. Initial and final byte maps expose every modeled RAM byte, including the explicit stack fill, caller's entry-stack word, handle field, errno word, and procedure frame/buffer writes. The separate `write_traces.py` regenerates traces; `validate.py` is read-only and verifies source binding, deterministic replay, expected outcomes and vectors, and unchanged package inventory.

Each fixture uses entry SP `0x8000`, sentinel-fills the modeled stack range with `0xa5`, sets word[entrySP] to `0xfeedface`, and provides a valid handle pointer `0x1000` with an explicitly initialized word at handle+4. The valid-pointer cases use FD words 0 and 7; `0xffffffff` at that field is signed-negative. Null and negative-handle cases both return local 1 before ioctl. The stack map records only explicit fixture bytes and executed writes: `SUB sp,#0x20` reserves space but does not zero it; actual STRB instructions write the two status bytes to zero.

For ReadWrite, the call boundary occurs at current SP `entrySP-40`, with `(r0=word[handle+4], r1=0x40184b01, r2=A=SP+8)`. The 24-byte region is six words: `0x11111111`, `0x22222222`, `0x33333333`, pointer SP+6, pointer SP+7, and `0x5dc`; the latter two target bytes are zero in the selected fixtures. For Command, `(r0=word[handle+4], r1=0x401c4b02, r2=A=SP+4)` and the 28-byte region contains the three entry-register words, `word[entrySP]=0xfeedface` loaded at current SP+0x28, pointers SP+2/SP+3, and `0x1388`. These are numeric vectors from the callsite, not prototypes or public buffer types.

Opaque boundaries are modeled as named, explicit fixture events with captured arguments, request/buffer bytes, selected result, and required preserved state. No provider code is run. For the ordinary ioctl fixtures, the event stipulates a normal return, unchanged SP, current r4 still 0, no writes to the two local status bytes, and the selected r0 result; r1–r3, r12, and NZCV are poisoned to demonstrate that only stated premises carry forward. `__errno_location` is modeled as a normal return of the fixture pointer `0x3000`; r4 need not survive that call because the source immediately overwrites it. ReadWrite's `strerror`/`syslog` events require the current errno pointer in r4 and the frame/SP to remain usable. Syslog may update the fixture errno word, and the following source LDR—not the earlier value—controls the result. These are explicit model effects, not ABI claims.

With r4 preserved as zero, both post-ioctl signed CMP/BGE sequences return local 0 for fixture results 0 and +1. A separate boundary-control case returns ioctl result 0 but changes current r4 to 1; the signed comparison falls through to the error route, demonstrating that success depends on current r4=0 as well as r0. A negative ioctl result reaches errno handling: Command returns2 for current errno `0x6e`, otherwise1 in the tested cases. ReadWrite calls the errno-location, strerror-, then syslog-named PLTs and reloads the word at current r4 afterward. Its final `0x3d` or `0x6e` gives2; tested other value `0x1234` gives1. The `neg_errno3d` fixture starts with errno1 at logger entry, changes the memory word to `0x3d` at the opaque syslog boundary, and confirms the final source LDR sees `0x3d`.

All selected normal/error traces execute the actual saved-register epilogue, restore SP to `0x8000`, restore initial r4, and return to the fixture continuation PC. The model does not assign meaning to request values, errno numbers, local return values, or status bytes beyond the numeric source behavior. No native ELF, device, VM, network, or kernel code was executed.
