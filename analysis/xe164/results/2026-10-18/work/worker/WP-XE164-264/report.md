# WP-XE164-264 — canonical review of WP-257 halfword provenance

**Status:** self-review, offline, bounded to the exact WP-257 bodies `CMLoadComponent3` `[0x2ffc84,0x2ffe08)` (388 bytes) and helper `[0x2fc530,0x2fc708)` (472 bytes), plus the pinned WP167/WP254/WP255 report summaries. The source is the 5,181,396-byte `codesys3` ELF, SHA-256 `b56c6296faabae9eb73f0463fd068c535c03109ced347f0c2a643b69a7ee1ab5`. Retained Ghidra records are used; no new REA import, callee expansion, ABI premise, or runtime claim is introduced. WP-257 and WP-261 remain unchanged and are pinned in `sourcepins/pins.tsv`.

At `0x2ffd00`, CMLoad computes `r2 = current r11 - 0x58`; define that current register value as `F` and the local block pointer as `B=F-0x58`. When the initialization path reaches `0x2ffd40`, `STRH` writes literal 2 to `[current r11-0x2c]`, which is `[B+0x2c]` within this uninterrupted sequence. The immediately written bytes are `[B+0x2c,B+0x2d]=[2,0]` on the little-endian target. This is **VERIFIZIERT local post-store**. Opaque calls occur before the local setup, so without ABI evidence F is not identified with the prologue frame value. No call occurs from `0x2ffd00` through `0x2ffd40`, which makes the local base-to-store relation valid. Later uses of `r11` after opaque calls are not equated with F absent preservation evidence. The preceding vector initialization at `B+0x2c..+0x33` and the adjacent halfword at `B+0x2e..+0x2f` are accounted for; the literal-2 store is last among direct CMLoad stores overlapping the target halfword.

The helper copies entry `r0` into `r4`, then calls the indirect target from `[B+0x10]` at `0x2fc5c8`. After that opaque call, `CMP r0,r6` at `0x2fc5cc` sends equal values to `0x2fc628`, bypassing `STRH`; unequal values continue to `STRH #3,[r4+0x2c]` at `0x2fc5dc`. No assumption says `r6` remains zero or that `r4` remains B. Therefore: (a) the exact local predicate for executing the syntactic store is post-call `r0 != r6`; (b) the syntactic target is **post-call `r4+0x2c`**; (c) it targets entry `B+0x2c` only if post-call r4 equals entry B. When those predicates both hold, the helper's direct store changes the halfword from 2 to 3. When the comparison is equal, this direct store is skipped. All rows in `helper-halfword-cases.tsv` preserve the separate `OPAQUE_MEMORY_EFFECTS_OPEN` qualification: the indirect call may itself mutate B on either comparison lane.

Other helper stores after the first BLX are also syntactically based on post-call r4 (`+0`, `+0xc`, `+0x14`, `+0x1c`, `+0x20`, `+0x24`). Their target is entry-B-relative only under the same r4 identity condition. The helper's later halfword load at `r4+0x2e` is adjacent and distinct from `+0x2c`. The branch table states the helper predicates as post-call register conditions, not ABI-derived entry values.

Direct caller initialization stores and helper syntactic stores are separated in `memory-effects.tsv`. The CMLoad prologue copies entry r3 to r5 at `0x2ffc90`, but opaque calls follow before four conditional 4-byte stores at `0x2ffdcc`, `0x2ffdd8`, `0x2ffdf0`, and `0x2ffe00`. Each instruction stores through **current r5**. A word store at current address A overlaps the local halfword `[B+0x2c,B+0x2d]` exactly when A lies in `[B+0x29,B+0x2d]`; the synthetic cases exercise both endpoints, neighboring non-overlap addresses, and whether current r5 equals entry r3. No preservation evidence identifies current r5 with entry r3. Opaque calls after initialization also have unresolved memory effects. The later instructions load at current `[r11-0x44]` and `[r11-0x40]`; these are B+`0x14` and B+`0x18` only if current r11 still equals F. Later pointer expressions computed from current r11 equal B under that same identity condition. No such identity is assumed across opaque calls.

The copy/pool/gate chain remains conditional: under the pinned WP167 summary, if exact B is the source of the reported 52-byte equal-offset copy, bytes 44–45 map to payload+`0x2c`; under WP254's pinned pool equations that position is numeric payload+`0x2c`; under WP255's pinned gate summary, value 2 is accepted among {2,4,5} if that same payload is the candidate object and the bytes are preserved. This does not prove source identity, runtime order, manager/node/object identity, or the absence of intervening writes. No field name or type is inferred.

The minimum evidence still needed for a later gate-value claim is: opaque first-BLX effects on B and post-call r4; subsequent opaque calls' effects; current-r5 address/disjointness evidence for each late word-store lane, plus preservation evidence before identifying current r5 with entry r3; exact B-to-copy-source and copy timing/byte preservation; exact pool payload/node identity; exact candidate object identity; and no intervening mutation through the gate read.
